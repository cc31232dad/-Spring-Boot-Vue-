# 环境与数据隔离设计

日期：2026-08-24

## 目标

为开发、测试和生产提供明确的 Spring profile 和数据边界，避免验收账号、测试数据、Redis 秒杀库存和上传文件互相污染。保持当前前后端分离的模块化单体结构，不增加新服务或业务表。

## 配置结构

- `application.yml` 保存公共默认值，并将默认 profile 设为 `dev`，保证本地不带参数也能启动。
- `application-dev.yml` 保存本地开发连接约定，可使用本机 MySQL/Redis；敏感值可由环境变量覆盖。
- `application-test.yml` 使用独立数据库名、Redis key 前缀和上传目录。测试不会连接开发数据库，也不会复用开发 Redis key。
- `application-prod.yml` 不写入账号、密码或密钥，数据库、Redis、JWT 密钥和上传目录全部从环境变量读取；缺少必需变量时启动失败。
- 上传目录按 profile 分开，数据库仍只保存图片 URL，不保存二进制。

## 数据边界

- MySQL：开发、测试、生产使用不同数据库名或不同实例；Flyway 在各自数据库独立迁移。
- Redis：每个 profile 使用独立 key 前缀，至少覆盖秒杀库存、用户限购和缓存键。
- 文件：开发、测试、生产使用独立上传目录；测试目录可在测试结束后清理。
- 验收账号和演示商品不自动进入生产配置或生产初始化流程。

## 验证

- 增加配置测试，断言测试 profile 的数据源、Redis 前缀和上传目录与开发不同。
- 增加生产配置检查，确认缺少必需环境变量时不能静默使用开发默认值。
- 运行后端全量测试、前端测试和构建，并执行 `git diff --check`。
- 更新交接文档，记录 profile 启动命令、环境变量名和数据清理责任。

## 明确不做

- 不新增 Docker 后端容器。
- 不实现支付、物流、评价或微服务拆分。
- 不自动删除现有本地验收数据；清理动作单独执行并需明确授权。
