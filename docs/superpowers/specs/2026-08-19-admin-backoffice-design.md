# 助农商城三端分离与双后台设计

## 目标

把现有系统整理为三个职责清晰的使用界面：买家使用公开商城，农户使用独立经营工作台，管理员使用独立平台后台。农户登录后进入 `/farmer`，完成商品与订单事务；管理员登录后进入 `/admin`，完成农户审核、商品审核和全局订单监管。两个后台沿用现有 Spring Boot API、JWT 和角色权限边界，不增加运营、客服、超级管理员或管理员创建功能。

## 产品边界

- 商城端主要服务买家，保留首页、商品详情、购物车、订单、用户中心、收藏和地址。
- 农户工作台服务 `FARMER`，拥有独立导航、顶部栏和经营页面，不再把商品管理与订单处理散落在商城布局中。
- 管理员后台服务 `ADMIN`，拥有独立导航、顶部栏、页面密度和平台监管视觉语言。
- 三个界面仍属于同一个 Vue 应用和同一个 Spring Boot 后端，不复制项目、不拆微服务。
- 农户与管理员都可通过“查看商城”进入公开目录，检查商品展示结果；商城不是他们的默认工作区。
- `FARMER` 与 `ADMIN` 登录后不显示买家的购物车、地址、收藏和个人订单入口，除非该账号实际同时拥有 `USER` 角色。
- 管理员登录成功后默认进入 `/admin`，不再落到商城首页。
- 后台提供明确的“查看商城”入口，便于管理员检查公开商品结果；这不是管理员的默认工作区。
- 普通买家、农户和未登录用户不能访问任何 `/admin` 页面，后端 `/api/admin/**` 继续作为最终权限边界。
- 本阶段不增加用户管理、管理员管理、营销配置、统计报表、运营/客服细分权限或新的数据库表。

## 路由与组件结构

系统形成三棵路由：

```text
/                              买家商城与公开目录
/user/**                       买家个人中心

/farmer                        FarmerLayout
├── /farmer                    FarmerDashboardView
├── /farmer/products           FarmerProductsView
├── /farmer/products/new       ProductFormView
├── /farmer/products/:id/edit  ProductFormView
└── /farmer/orders             FarmerOrdersView

/admin                         AdminLayout
├── /admin                     AdminDashboardView
├── /admin/products            AdminProductsView
├── /admin/farmers             AdminFarmersView
└── /admin/orders              AdminOrdersView
```

`FarmerLayout.vue` 负责农户经营后台外壳：

- 导航只包含工作台、商品管理和订单处理；
- 顶部显示当前页面、农户账号、查看商城和退出；
- 新建/编辑商品继续使用现有表单和 API；
- 移动端使用可展开菜单；
- 不显示农户审核、全局商品审核和全局订单。

管理员路由改为嵌套结构：

```text
/admin                         AdminLayout
├── /admin                    AdminDashboardView
├── /admin/products           AdminProductsView
├── /admin/farmers            AdminFarmersView
└── /admin/orders             AdminOrdersView
```

`AdminLayout.vue` 负责后台外壳，不承载具体业务：

- 桌面端固定左侧导航；
- 顶部显示当前页面、管理员账号和退出操作；
- 主内容区渲染子路由；
- 提供“查看商城”链接；
- 移动端将侧栏收为可展开导航，避免遮挡内容。

三个已有管理员页面只改为后台内容页，删除各自重复的“返回商城”、大标题外壳和商城式页面边距。审核与订单请求仍通过现有 `src/api` 和 Pinia Store 完成，不复制接口逻辑。

现有农户商品页、商品表单和农户订单页改为 `FarmerLayout` 子页面，删除各自重复的返回商城外壳。商城、农户和管理员共享认证 Store 与 API 层，不共享布局组件。

## 登录与导航行为

- 登录页继续提供买家、农户和内部管理员三种身份入口。
- 登录成功后先加载当前用户；`ADMIN` 默认跳转 `/admin`，`FARMER` 默认跳转 `/farmer`，`USER` 默认跳转商城首页。
- 带合法 `redirect` 参数时优先返回目标路由，但管理员不能借此绕过目标路由的角色限制。
- 商城首页对 `ADMIN` 显示“进入管理后台”，对 `FARMER` 显示“进入农户工作台”；不为这两类单角色账号显示买家专属入口。
- 两个后台退出后均回到 `/login`。
- 用户直接访问 `/admin/**` 时，未登录跳登录页；角色不符跳商城首页并不渲染后台布局。
- 用户直接访问 `/farmer/**` 时，未登录跳登录页；非农户角色跳商城首页并不渲染农户布局。`ADMIN` 不自动获得农户经营权限。

## 农户工作台数据

`FarmerDashboardView.vue` 只使用农户本人真实数据：

- `GET /api/farmer/products`：本人商品总数、待审核、已上架、已拒绝和已下架数量；
- `GET /api/farmer/orders`：本人订单总数、待发货数量和最近订单。

工作台显示商品状态概览、待处理订单入口和最近订单。某一接口失败时保留另一模块的数据，并提供区域级重试。不得使用全平台商品、其他农户订单、虚构销售额、趋势或排名。

## 工作台数据

`AdminDashboardView.vue` 使用现有真实接口并行加载：

- `GET /api/admin/products/review?status=PENDING_REVIEW`：待审核商品数；
- `GET /api/admin/products/review?status=ON_SALE`：已上架商品数；
- `GET /api/admin/farmers`：待审核农户数；
- `GET /api/admin/orders`：平台订单数和最近订单。

工作台显示四个紧凑指标、待处理事项和最近订单，不生成没有真实来源的销售额、趋势、同比、未读红点或图表。某一接口失败时保留其他已加载数据，并在对应区域显示可重试错误，不把所有模块一起置空。

## 信息架构

农户侧栏保持三个一级入口：

1. 工作台
2. 商品管理
3. 订单处理

商品管理保留新建、编辑、重新提交和下架；订单处理保留已有发货能力。农户只能看到本人数据，后端所有权校验继续作为最终边界。

左侧导航保持四个一级入口：

1. 工作台
2. 商品审核
3. 农户审核
4. 订单管理

顶部栏使用面包屑表达当前位置。商品和农户审核操作保持“通过”和“拒绝”；拒绝必须填写原因并二次确认。订单页本阶段只读，统一改为简体中文，不添加后端尚未支持的退款、发货或删除按钮。

## 视觉设计

参考图只采用“左侧导航 + 顶部栏 + 内容工作区”的后台骨架，去掉手机商品、品牌管理、营销、SKU 编辑、Apple 图标和无关操作。

两个后台共享助农商城的基础色彩和控件标准，但用不同侧重点区分职责：

- 农户工作台主题为“田间作业簿”，使用叶片绿侧栏、暖白工作区和更直接的经营状态提示；
- 管理员后台主题为“田间档案室”，使用更深的森林绿侧栏、更高信息密度和监管状态提示。

管理员视觉色板：

- `档案绿 #173F2B`：后台侧栏和主导航底色；
- `叶片绿 #2F7D4A`：选中状态、主要按钮和链接；
- `稻穗金 #D9A441`：待处理强调和键盘焦点；
- `纸张白 #FFFFFF`：表格、工具栏和内容背景；
- `雾灰绿 #F3F6F2`：后台工作区背景；
- `泥土墨 #26362B`：正文和数据文字。

字体继续使用系统中文无衬线字体，数据、状态和表格标题采用更紧凑的字号与字重。后台不使用商城 Hero、商品营销卡片、渐变装饰或大圆角；面板圆角不超过 8px。

后台的识别性元素是侧栏顶部的“田垄刻度”：品牌标志下方用短横分隔线表达农田行距，同时作为导航分组边界。该元素只出现一次，其余页面保持安静、工具化。

农户工作台使用同一田垄刻度，但以叶片绿表现，并在工作台顶部用一条紧凑的“本日待办”横栏呈现待审核商品与待发货订单，不使用大尺寸数据 Hero。

桌面布局：

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 助农商城后台  │ 后台 / 当前页面               管理员账号 退出 │
│ 田垄刻度      ├──────────────────────────────────────────────┤
│ 工作台        │                                              │
│ 商品审核      │              子路由工作区                     │
│ 农户审核      │                                              │
│ 订单管理      │                                              │
│              │                                              │
│ 查看商城      │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

移动端：两个后台都在顶部显示品牌、当前页面和菜单按钮；展开菜单后纵向展示各自入口。指标改为两列或一列，商品、审核和订单列表从横向表格降级为信息分组卡片，所有操作按钮保持可触达且文字不溢出。

## 状态、错误与可访问性

- 页面首次加载显示区域级加载状态；刷新按钮有禁用状态。
- 空状态说明当前没有待处理事项，不使用模糊文案。
- 待审核使用暖黄色，通过/上架使用绿色，拒绝使用砖红色，下架/取消使用中性灰。
- 当前导航项使用 `aria-current="page"`；移动菜单按钮提供可读名称和展开状态。
- 所有输入框、按钮和链接有可见键盘焦点；颜色不是状态的唯一表达方式。
- 审核失败保留用户已填写的拒绝原因，便于重试。
- 农户商品提交、重新提交、下架和订单发货失败时保留当前页面上下文，显示可执行的重试提示。

## 测试与验收

前端自动测试覆盖：

- `ADMIN` 登录后进入 `/admin`；
- `FARMER` 登录后进入 `/farmer`；
- `USER` 和 `FARMER` 不能进入管理员后台布局；
- `USER` 和 `ADMIN` 不能进入农户布局；
- 农户所有子路由都带 `FARMER` 角色限制；
- 后台四个子路由都带 `ADMIN` 角色限制；
- 工作台正确汇总四类现有接口数据，部分接口失败时保留成功模块；
- 农户工作台正确汇总本人商品和订单状态，部分接口失败时保留成功模块；
- 后台导航、退出和查看商城入口行为正确；
- 农户导航、退出和查看商城入口行为正确；
- 订单页面中文状态与空/错/加载状态正确。

浏览器验收覆盖桌面和移动视口：

1. 管理员通道登录后直接进入工作台；
2. 侧栏切换商品审核、农户审核和订单管理时不进入商城布局；
3. 审核操作仍调用真实后端并刷新待处理数量；
4. 查看商城能打开公开商城，商城提供返回后台入口；
5. 买家或农户直接访问 `/admin` 被阻止；
6. 侧栏、顶部栏、内容和操作按钮在常见桌面与手机宽度下不重叠。
7. 农户登录后直接进入 `/farmer`，可以在独立工作台完成商品提交、查看审核状态和订单发货，不出现管理员菜单。
8. 买家、农户、管理员在各自默认界面中只看到符合自身角色的导航；查看商城入口不改变其权限。
